On ouvre un projet Cursor, ou une session Claude Code. Les skills sont là, dans le dépôt. On les a écrites pour un modèle qui avait besoin d'être tenu par la main. Elles se chargent encore, comme si rien n'avait changé.

Ce n'est pas que ces textes soient faux. C'est qu'ils ont été calibrés pour une capacité. Le modèle a bougé. Les instructions, non. On continue d'injecter un mode d'emploi écrit pour quelqu'un qui ne savait pas encore.

On dirait un GPS resté en mode débutant alors que le conducteur connaît le quartier. Le guidage n'aide plus : il raccourcit le regard. Une skill utile hier devient un rail. Elle force des étapes et des précautions qui avaient un sens. Aujourd'hui, elles empêchent parfois le modèle de faire ce qu'il sait déjà, ou lui font répéter un ancien contournement.

La revue des skills n'est pas de la documentation. C'est aligner les instructions sur le modèle actuel, pas sur celui qu'on avait en tête. Combien de fichiers, dans vos dépôts, décrivent encore une limitation que le modèle n'a plus ?
